# Онлайн-кампания Warcraft: Век Авантюристов

Проект Supabase **Azeroth Atlas Shattered** уже указан в клиенте. В браузере используется только публичный ключ publishable. GitHub Pages обслуживает статические файлы. Вход по почте, общая кампания и изображения работают через Supabase.

В этой версии участники могут смотреть опубликованную схему карты и свои профили. Мастер может привязывать героев и переносить сохранение. Золото, инвентари, награды, броски и расход времени остаются в закрытой копии кампании. Онлайн-операции над ними откроются после переноса проверок на сервер. Локальная версия запускается как раньше и хранит отдельную копию.

## 1. Настроить Auth

1. Откройте [проект Supabase](https://supabase.com/dashboard/project/grllbjrsygszfqnllnsa). В **Authentication → Providers / Sign In** оставьте включённым провайдер **Email**. Отключите **Allow new users to sign up**.
2. В **Authentication → Users → Add user** создайте аккаунт мастера с email и паролем. Для вручную созданного аккаунта отметьте **Auto Confirm User**, если адрес уже проверен. Скопируйте **User UID**. Точно так же создаются учётные записи остальных участников.
3. В **Authentication → URL Configuration** установите **Site URL** `https://www.atlas-shhatered-world.ru/` по текущему `CNAME`. Если используете стандартный адрес Pages, выберите `https://egorzubakin-sudo.github.io/wow-dnd/`. В **Redirect URLs** добавьте `https://www.atlas-shhatered-world.ru/index.html?online=1` или соответствующий URL стандартного домена, если будете использовать письма Supabase. Для входа с паролем перенаправление не требуется.

## 2. Применить миграцию и назначить мастера

1. После проверки откройте **SQL Editor → New query**, вставьте содержимое [миграции](supabase/migrations/202611270001_atlas_online.sql) и выполните её один раз. Она создаст таблицы, политики RLS, закрытый бакет `atlas-campaign-media` и добавит таблицу версий в публикацию Realtime.
2. Выполните отдельно приведённый запрос. Подставьте UID мастера, название кампании и никнейм.

```sql
with new_campaign as (
  insert into public.atlas_campaigns (name)
  values ('Вольная компания')
  returning id
)
insert into public.atlas_members (campaign_id, user_id, nickname, role)
select id, 'UID-МАСТЕРА-ИЗ-AUTH'::uuid, 'Мастер', 'master'
from new_campaign
returning campaign_id;
```

3. В **Storage** проверьте, что `atlas-campaign-media` помечен **Private**. В **Database → Publications** проверьте, что `supabase_realtime` содержит `public.atlas_campaigns`. Оно передаёт участникам номер версии и название кампании.

## 3. Включить GitHub Pages

1. После настройки Supabase влейте ветку `atlas/supabase-online` в `main`. В [настройках Pages репозитория](https://github.com/egorzubakin-sudo/wow-dnd/settings/pages) выберите **Deploy from a branch → main → / (root) → Save**. Файл `.nojekyll` позволяет отдавать файлы сборки напрямую. Если Pages недоступен для приватного репозитория на вашем тарифе GitHub, потребуется тариф с Pages для приватных репозиториев или отдельный публичный репозиторий сборки.
2. Дождитесь статуса публикации в GitHub. Откройте [онлайн-версию на своём домене](https://www.atlas-shhatered-world.ru/) или [стандартный адрес Pages](https://egorzubakin-sudo.github.io/wow-dnd/index.html?online=1) и войдите с почтой и паролем мастера. На GitHub Pages корневой адрес открывает онлайн-вход. Параметр `?online=0` открывает локальную копию в браузере.

## 4. Перенести кампанию и выдать доступ

1. В вашей локальной кампании откройте **Мастерская → Импорт и экспорт → Экспорт JSON**. Сохраните эту копию отдельно.
2. В онлайн-версии откройте **Импорт и экспорт**, выберите JSON и подтвердите импорт. Герои сохраняют старые ID. Пароли и локальные аккаунты из IndexedDB не переносятся.
3. Если карта подходит для общего просмотра, включите публикацию известных мест и маршрутов. Отдельная галочка открывает участникам подложку общей карты, если включена схема, и личные портреты владельцам героев. Секретные отметки, нарисованные прямо на подложке, являются частью изображения. Проверьте подложку перед публикацией.
4. Откройте **Аккаунты и герои**, введите UID участника из **Authentication → Users**, задайте игровой никнейм и роль. Назначьте героя игроку или капитану. Наблюдателю доступны опубликованная карта и его собственная учётная запись.
5. Проверьте вход участника в другом браузере. Участник видит опубликованные данные и назначенных героев. Полный экспорт, импорт и управление составом доступны мастеру.
6. Перед заменой уже перенесённой кампании скачайте её текущий JSON из онлайн-версии. Скачанный файл включает изображения и открывается локальным импортом Атласа. Мастер может удалить изображения от предыдущих и незавершённых загрузок через раздел импорта. Активные изображения сохраняются.

Отдельное изображение ограничено 20 МиБ, JSON без изображений — 8 МиБ. Изображения одинакового содержимого внутри одного импорта загружаются один раз. Подложка и портрет скачиваются по запросу при открытии. Realtime обновляет номер версии и перечитывает открытую карту или список героев. Полное сохранение загружается в браузер только при экспорте мастером.

## Проверки до публикации

- `python3 scripts/build.py` собирает страницы.
- `node tests/core.cjs` и `python3 tests/browser.py` проверяют локальную версию.
- `bash tests/online-db.sh` применяет SQL к временному PostgreSQL 17 со схемами-имитациями Auth и Storage и проверяет роли, выдачу изображений и закрытые поля.
- `python3 tests/online-browser.py` проверяет браузерный клиент Supabase с локально подменёнными ответами Auth, REST и Storage. Для проверки на вашем проекте сначала выполните шаги в панели Supabase.
