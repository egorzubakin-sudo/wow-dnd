# Пакеты контента Атласа

Пакет — один JSON-файл. Его можно создать отдельно от приложения и установить через **Мастерская → Пакеты контента → Проверить пакет**. Кнопка **Скачать спецификацию для генерации контента** выдаёт актуальную схему, форматы полей, перечисления, единицы, шаблон пакета и связанный пример. Тот же справочник хранится в [data/schema.json](data/schema.json).

## Структура пакета

| Поле | Значение |
| --- | --- |
| format, schemaVersion | atlas-content и 1 |
| id | Постоянный ID пакета. Например, region.barrens.trade |
| name, description, author | Название, назначение и автор |
| version | Версия X.Y.Z. Для обновления увеличьте хотя бы один разряд |
| sources | Массив объектов происхождения |
| dependencies | Массив объектов вида {"id":"core.book-equipment","minVersion":"1.0.0"} |
| tables | Объект с ключами справочников. Значение каждого ключа — массив записей с постоянными ID |

    {
      "format": "atlas-content",
      "schemaVersion": 1,
      "id": "campaign.copper",
      "name": "Медные припасы",
      "description": "Дополнение к справочнику материалов.",
      "version": "1.0.0",
      "author": "Мастер кампании",
      "sources": [{"origin": "house"}],
      "dependencies": [],
      "tables": {
        "materials": [
          {
            "id": "material.campaign.copper_ore",
            "name": "Медная руда",
            "category": "Материалы",
            "quality": "common",
            "value_gp": 1,
            "source": {"origin": "house"}
          }
        ]
      }
    }

## Идентификаторы и связи

Выбирайте пространственные имена, например recipe.smithing.copper_bar, goods.smithing.apprentice и quest.barrens.supply_01. Используйте прежние ID, когда ссылаетесь на существующие сущности. Длина ID — от 1 до 128 символов. Допустимы буквы, цифры, точка, двоеточие, дефис и подчёркивание. Отображаемое имя можно менять отдельно.

Положите зависимые строки в тот же пакет или перечислите пакеты-поставщики в dependencies. Ссылки на системные профессии вроде smithing доступны из базового справочника. Отсутствующая запись, конфликт владельцев ID и циклическая зависимость отклоняются при проверке. Представления одной коллекции используют общие ID. Например, не дублируйте один предмет одновременно в items и tradeGoods.

## Что передать генератору контента

1. Приложите скачанную спецификацию и при необходимости экспорт справочников кампании.
2. Укажите ID и версию пакета, требуемый объём, источники, границы домашних правил и список доступных зависимостей.
3. Попросите вернуть один JSON в формате atlas-content со стабильными ID. Проверьте список источников, числа и связи.
4. Откройте JSON в Мастерской, посмотрите список созданий, изменений и конфликтов и подтвердите установку.

Готовый связанный пример с регионами, NPC, добычей, рецептами, рынком, поручением и поставкой доступен отдельно. [Учебный пакет](content/examples/trade-loop.json) · [Книжная экипировка](content/core/book-equipment.json)

## Справочники и источники

В машиночитаемой схеме у каждого поля есть purpose, type, optional, allowed, default, unit, reference и example. Пустые необязательные поля используют поведение движка. Поле extra CSV хранит дополнительные JSON-поля для кругового импорта. Случайные события маршрута хранятся в routes.events, а материалы рецептов и варианты решений задания — в связанных таблицах. Поставки используют deliveries.goods и deliveries.rewards. [Схема](data/schema.json) · [Шаблоны](data/templates/)

Для книги указывайте {"book":"phb2024","printed_page":215}, dmg2024 или wow. Для авторских и демонстрационных строк используйте {"origin":"house"} и {"origin":"demo"}. В записях, где source уже обозначает рассказчика, занятие NPC или издателя, структурированное происхождение хранится в provenance. У книжного предмета правила лежат в rules. Золото, длительность и доступность кампании задаются в полях экономики и рецептов.

## Обновление и резерв

Пакет с новой версией можно применить после предпросмотра и подтверждения. Оставшиеся в кампании записи старой версии сохраняются. Чтобы вывести пакет из списка действующих зависимостей, архивируйте его. Пакет, на который ссылаются действующие пакеты, архивировать нельзя. Установленные записи и история сохраняются.

Запас, спрос и бюджет рынка сохраняются при обновлении пакета. Для планового пополнения включите соответствующий флажок в предпросмотре или измените строки непосредственно в справочнике. Рабочие проекты сохраняют снимок рецепта. Предметы в сумках сохраняют индивидуальные свойства. Данные о репутации, знакомстве и выполнении заданий сохраняются.

Экспорт пакета содержит определения справочников. Квитанции выполненных поставок и история знакомств входят в резервную копию кампании.

Импорт записывает обновлённую кампанию и резерв перед ним в одной транзакции IndexedDB. Для возврата используйте историю действий в текущем сеансе или скачайте резерв из окна пакетов и загрузите его обычным импортом кампании.
