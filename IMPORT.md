# Как заполнить шаблон импорта Атласа

Откройте **Мастерская → Мастерская данных**, выберите справочник и скачайте **Пустой шаблон** или **Пример**. Поля со звёздочкой в блоке **Поля и формат данных** обязательны.

- В CSV сохраните названия столбцов. Одна строка — одна запись. Сохраняйте файл в UTF‑8 с разделителем `;`. Необязательные ячейки можно оставить пустыми. Для полей да/нет используйте `true` и `false`.
- `id` — уникальный ключ внутри справочника. Например, `copper-ore`. При изменении названия оставьте прежний `id`. В поля ссылок вроде `item_id` или `region_id` вписывайте ключ нужной записи.
- В поля типа JSON вписывайте массивы или объекты. Например, значение `tools` в редакторе таблиц — `["Инструменты кузнеца"]`. Если пишете CSV вручную, удвойте кавычки внутри ячейки: `"[""Инструменты кузнеца""]"`.

| Справочник | Как заполнить основные поля |
| --- | --- |
| Профессии | `id`, `name`. Для `kind` используйте `gathering` (добыча) или `production` (производство). `summary` — текст карточки, `description` — описание механики, `special` — особые правила. `tools` — альтернативные инструменты, достаточно владеть одним из списка. |
| Предметы | `id`, `name`, `category` из справочника, например `Материалы`. `quality` — `common`, `uncommon`, `rare`, `epic` или `legendary`. `value_gp` — цена в зм, допустим `0`. |
| Рецепты | `profession_id` — профессия, `item_id` — результат, `quantity` — выход за одно изготовление, `hours` — целые часы, `rank` — требуемый бонус владения. `gold` задаёт затраты в зм. |
| Ингредиенты | `recipe_id` и `item_id` связывают рецепт с сырьём. `quantity` — расход сырья за одно изготовление. |
| Регионы и добыча | У региона укажите `id`, `name` и `dc` (сложность). В добыче свяжите `region_id`, `profession_id` и `item_id`. `weight` — относительный вес находки. `min_quantity` и `max_quantity` — границы количества. `min_margin` — на сколько нужно превысить Сл. Укажите `0`, если достаточно сравняться со Сл. |
| Местные поручения | `id`, `title`, `hours` и при необходимости `region_id`. Для вариантов заполните таблицу «Решения поручений» со ссылкой `quest_id`, для наград используйте `solution_id`. |

## Пример связанного пакета

В кампании уже должна быть профессия `smithing`. Сохраните пример как JSON и загрузите его целиком. Мастерская проверит ссылки между таблицами в одном пакете.

```json
{
  "items": [
    {"id":"example-ore","name":"Медная руда","category":"Материалы","quality":"common","value_gp":1},
    {"id":"example-bar","name":"Медный слиток","category":"Материалы","quality":"common","value_gp":3}
  ],
  "recipes": [
    {"id":"example-smelt","name":"Выплавка меди","profession_id":"smithing","item_id":"example-bar","quantity":1,"hours":2,"rank":2}
  ],
  "ingredients": [
    {"id":"example-smelt-ore","recipe_id":"example-smelt","item_id":"example-ore","quantity":2}
  ]
}
```

Новые записи загружайте в режиме **Только новые**. Для правок выбирайте **Обновить по ID**. Режим **Пропустить конфликты** оставляет совпадающие записи как есть. Режим **Полная замена** заменяет содержимое выбранного справочника.

Нажмите **Проверить и просмотреть**. Если мастерская сообщает об отсутствующей связи, сверьте ключ и убедитесь, что связанная запись уже есть в кампании или пакете. После проверки нажмите **Подтвердить импорт**.

## Рынки, поставки и пакеты

**Мастерская → Пакеты контента** принимает JSON с метаданными, зависимостями и связанными таблицами. Для CSV используйте разделитель «точка с запятой» и UTF-8 с BOM. Экспорт сохраняет вложенные и дополнительные поля в JSON-колонках, включая extra.

| Справочник | Что заполнить |
| --- | --- |
| tradeGoods, tradeRecipes, ingredients | Товар, его профессия, качество и цена. Рецепт и отдельные строки материалов |
| markets | Узел, товар, необязательная фракция, запас, спрос, бюджет и множители цен. При необходимости rep_bonuses |
| facilities, services, campUpgrades | Сооружение и цены, местные предложения аренды или наставник, эффекты улучшения для существующего дерева |
| deliveries | Узел, срок, имя получателя, массив товаров и наград, источник запасов и получатель награды |
| originalEquipment, craftProperties | Исходные параметры и печатная страница. Для домашних свойств — вид, триггер, действие, эффект, ограничения и восстановление |

Поля каждого справочника и полные примеры есть в [data/schema.json](data/schema.json). Руководство для упаковки связанных записей находится в [CONTENT_GUIDE.md](CONTENT_GUIDE.md).

## Карты и отметки

- `maps` задаёт карту. Сошлитесь на `overview` в `parent_id` для первого дочернего уровня. `kind` принимает `world`, `continent`, `region`, `local`. Подложку можно загрузить отдельно из настроек карты.
- `mapPlacements` связывает `map_id` с существующим `node_id`. Задайте `x` и `y` от 0 до 1. Поле `child_id` ведёт на карту следующего уровня.
- `routeGeometries` связывает `map_id` и `route_id`. На этой карте должны стоять оба конца маршрута. В `points` укажите пары `[x,y]` по порядку. Допустимы `line` и `smooth`.
- `regionBoundaries` связывает `map_id` и `region_id`. В `points` укажите не менее трёх вершин по периметру. Отметки внутри контура определяют принадлежность места к региону.

Загрузите связанные таблицы одним JSON или импортируйте сначала карты, места, маршруты и регионы, затем отметки, линии и границы. Шаблоны доступны в Мастерской. [Пример пакета карт](content/examples/cartography.json)
